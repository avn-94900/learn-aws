

# 12. Infrastructure and Governance

## 1. What is AWS CloudFormation, and why is it used?

**Answer:**

AWS CloudFormation is a service to **define and provision AWS infrastructure using code (templates)**.

### Why it is used:

* Automates infrastructure creation
* Ensures consistency across environments (dev, test, prod)
* Supports **Infrastructure as Code (IaC)**

### Example:

Instead of manually creating:

* EC2
* RDS
* VPC

You define them in a template → deploy automatically

---

### Challenge your thinking:

Many think “CloudFormation = just automation” → incomplete

👉 Real value:

* Version control (like code)
* Repeatability
* Safe updates (rollback support)

---

## 2. What are CloudFormation stacks and templates?

**Answer:**

### Template

* JSON/YAML file
* Defines resources (EC2, S3, IAM, etc.)

### Stack

* A **running instance** of a template

---

### Simple analogy:

* Template = blueprint
* Stack = actual building

---

### Key features:

* Dependency management
* Rollback on failure
* Change sets (preview changes)

---

### Common mistake:

People think:
“Updating template automatically updates infra safely”

👉 Not always:

* Wrong change → can delete resources

---

## 3. What is AWS Systems Manager, and what problems does it solve?

**Answer:**

AWS Systems Manager is a service to **manage, monitor, and automate operations across AWS resources**.

---

### Problems it solves:

### 1. No SSH access needed

* Use Session Manager to connect securely

👉 More secure than opening ports

---

### 2. Patch management

* Automatically update OS/software

---

### 3. Configuration management

* Maintain consistent system setup

---

### 4. Automation

* Run scripts across multiple instances

---

### 5. Parameter Store

* Store configs/secrets securely

---

### Reality check:

Many teams ignore Systems Manager → rely on SSH

👉 That creates:

* Security risks
* Manual work

---

## 4. What is AWS Config, and how does it help governance?

**Answer:**

AWS Config tracks **configuration changes and compliance of AWS resources**.

---

### What it does:

* Records resource state (like EC2, S3)
* Tracks changes over time
* Evaluates compliance using rules

---

### Example:

Rule:

* “S3 buckets must not be public”

If violated → alert triggered

---

### Why important:

* Audit & compliance
* Security monitoring
* Change tracking

---

### Critical thinking:

CloudWatch tells **what happened (metrics/logs)**
AWS Config tells **what changed (configuration)**

---

## 5. What is AWS Organizations, and why is it used?

**Answer:**

AWS Organizations helps manage **multiple AWS accounts centrally**.

---

### Why it is used:

### 1. Account grouping

* Organize accounts into Organizational Units (OUs)

---

### 2. Central billing

* One bill for multiple accounts

---

### 3. Policy control

* Apply rules across accounts

---

### 4. Isolation

* Separate environments:

  * Dev
  * Test
  * Prod

---

### Challenge assumption:

Many use single AWS account → risky

👉 Better approach:

* Multi-account strategy for:

  * Security
  * Cost control
  * Fault isolation

---

## 6. What is a Service Control Policy (SCP), and how does it restrict access?

**Answer:**

SCP is a policy in AWS Organizations that **defines the maximum permissions** for accounts.

---

### Key idea:

* SCP does NOT grant permissions
* It only **restricts what is allowed**

---

### Example:

If SCP says:

* “No EC2 in region X”

👉 Even if IAM allows it → action is denied

---

### Important behavior:

Final permission =
👉 IAM अनुमति ∩ SCP सीमा

---

### Common misunderstanding:

People think SCP replaces IAM → wrong

👉 IAM = grants access
👉 SCP = sets boundaries

---
