

# 1. Cloud Fundamentals

# 1.1 Cloud Computing Basics

## What is cloud computing, and what are its key characteristics?

### Explanation

Cloud computing means using computing resources (servers, storage, databases, networking, software) over the internet instead of owning physical hardware.

Instead of buying servers, you rent them from a cloud provider and pay only for what you use.

### Key Characteristics (AWS / Industry Standard)

| Characteristic         | Meaning                                                    | Real Example                            |
| ---------------------- | ---------------------------------------------------------- | --------------------------------------- |
| On-Demand Self-Service | Create resources whenever needed without human interaction | Launch EC2 instance from console        |
| Broad Network Access   | Services available over internet                           | Access app from mobile/laptop           |
| Resource Pooling       | Multiple users share same infrastructure                   | Many companies use same AWS data center |
| Rapid Elasticity       | Scale resources quickly                                    | Add servers during traffic spike        |
| Measured Service       | Pay only for usage                                         | Pay for storage used in S3              |

### Strong Interview Answer

Cloud computing is the delivery of computing services over the internet on a pay-as-you-go basis. Its key characteristics include on-demand provisioning, elasticity, resource pooling, broad network access, and measured billing.

---

## What is the difference between Public, Private, Hybrid, and Multi-Cloud models?

### Comparison Table

| Model         | Description                                   | Example Use Case                               |
| ------------- | --------------------------------------------- | ---------------------------------------------- |
| Public Cloud  | Infrastructure shared across customers        | Hosting website on AWS                         |
| Private Cloud | Dedicated infrastructure for one organization | Banking systems                                |
| Hybrid Cloud  | Mix of on-premises and public cloud           | Store sensitive data locally, run app in cloud |
| Multi-Cloud   | Using multiple cloud providers                | AWS + Azure together                           |

### Key Differences

| Factor     | Public         | Private      | Hybrid   | Multi-Cloud        |
| ---------- | -------------- | ------------ | -------- | ------------------ |
| Ownership  | Cloud provider | Organization | Both     | Multiple providers |
| Cost       | Low            | High         | Medium   | Medium–High        |
| Control    | Less           | Full         | Balanced | Distributed        |
| Complexity | Low            | Medium       | High     | High               |

### Strong Interview Answer

Public cloud is shared infrastructure managed by providers like AWS. Private cloud is dedicated infrastructure for a single organization. Hybrid cloud combines on-premises with public cloud, while multi-cloud means using services from multiple cloud providers.

---

## What is the difference between on-demand provisioning, elasticity, and auto scaling?

### Comparison Table

| Term                   | Meaning                               | Who Controls      |
| ---------------------- | ------------------------------------- | ----------------- |
| On-Demand Provisioning | Create resources manually when needed | User              |
| Elasticity             | System automatically adapts to demand | System capability |
| Auto Scaling           | Automatically adds/removes instances  | AWS Auto Scaling  |

### Example

* On-Demand → Launch EC2 manually
* Elasticity → Infrastructure supports growth
* Auto Scaling → Automatically increases EC2 instances

### Strong Interview Answer

On-demand provisioning means creating resources whenever needed. Elasticity refers to the ability to dynamically adjust resources. Auto Scaling is a specific AWS service that automatically increases or decreases resources based on demand.

---

## What is the difference between vertical scaling and horizontal scaling?

### Comparison Table

| Feature         | Vertical Scaling       | Horizontal Scaling     |
| --------------- | ---------------------- | ---------------------- |
| Method          | Increase machine power | Add more machines      |
| Example         | Increase CPU/RAM       | Add more EC2 instances |
| Downtime        | Often required         | Usually none           |
| Limit           | Hardware limit         | Practically unlimited  |
| Fault Tolerance | Low                    | High                   |

### Strong Interview Answer

Vertical scaling increases the capacity of a single machine, while horizontal scaling adds more machines to distribute load. Horizontal scaling is preferred in cloud systems because it improves fault tolerance and scalability.

---

## What is the difference between scale-in and scale-out, and when should each be used?

### Comparison Table

| Term      | Meaning            | When Used         |
| --------- | ------------------ | ----------------- |
| Scale-Out | Add more instances | Traffic increases |
| Scale-In  | Remove instances   | Traffic decreases |

### Example

* Scale-Out → Festival sale traffic spike
* Scale-In → Night-time low traffic

### Strong Interview Answer

Scale-out means adding more resources to handle increased load, while scale-in means removing resources when demand decreases. This helps optimize performance and cost.

# 1.2 AWS Core Concepts

---

## What is AWS, and what are its key features?

### Explanation

Amazon Web Services (AWS) is a cloud computing platform that provides services like computing, storage, networking, databases, and security.

### Key Features

| Feature               | Meaning                                  |
| --------------------- | ---------------------------------------- |
| Global Infrastructure | Regions and Availability Zones worldwide |
| Pay-As-You-Go         | Pay only for usage                       |
| High Availability     | Built-in redundancy                      |
| Security              | IAM, encryption                          |
| Scalability           | Auto scaling support                     |

### Strong Interview Answer

AWS is a cloud platform that provides scalable and reliable computing services. Its key features include global infrastructure, pay-as-you-go pricing, built-in security, scalability, and high availability.

---

## Explain the AWS Shared Responsibility Model

### Core Idea

Security responsibilities are shared between AWS and the customer.

---

### Responsibility Table

| Layer          | AWS Responsibility | Customer Responsibility |
| -------------- | ------------------ | ----------------------- |
| Hardware       | Data centers       | —                       |
| Networking     | Physical network   | Firewall rules          |
| Virtualization | Hypervisor         | OS configuration        |
| OS             | —                  | OS patching             |
| Applications   | —                  | Application security    |
| Data           | —                  | Encryption & backups    |

---

### Responsibility by Service Type

| Model               | AWS Manages              | Customer Manages |
| ------------------- | ------------------------ | ---------------- |
| IaaS (EC2)          | Hardware, virtualization | OS, apps, data   |
| PaaS (RDS)          | OS, DB software          | DB data          |
| Serverless (Lambda) | Infrastructure           | Code             |

---

### Strong Interview Answer

In the shared responsibility model, AWS secures the infrastructure, while customers secure their applications and data. In IaaS, customers manage the OS and applications, while in serverless models AWS manages most infrastructure components.

---

## What is the difference between Regions and Availability Zones?

### Comparison Table

| Feature        | Region              | Availability Zone         |
| -------------- | ------------------- | ------------------------- |
| Definition     | Geographic location | Data center within region |
| Distance       | Far apart           | Close but isolated        |
| Failure Impact | Regional outage     | AZ outage                 |
| Example        | Mumbai region       | ap-south-1a               |

### Strong Interview Answer

A region is a geographic location containing multiple Availability Zones. Availability Zones are isolated data centers within a region that provide fault isolation and high availability.

---

## What is Multi-AZ deployment, and when should it be used?

### Explanation

Multi-AZ means deploying resources across multiple Availability Zones to improve availability.

### Use Cases

* Databases (RDS Multi-AZ)
* High availability systems
* Production workloads

### Strong Interview Answer

Multi-AZ deployment distributes resources across multiple Availability Zones to protect against zone failures. It should be used for critical applications that require high availability and automatic failover.

# 1.3 High Availability and Fault Tolerance

---

## How do you design a highly available and fault-tolerant architecture in AWS?

### Key Design Steps

1. Use multiple Availability Zones
2. Use Load Balancer
3. Enable Auto Scaling
4. Use Multi-AZ databases
5. Backup data regularly
6. Monitor using CloudWatch

---

### Typical Architecture

User → Load Balancer → EC2 Instances (Multi-AZ) → Database (Multi-AZ)

---

### Strong Interview Answer

To design a highly available system, distribute resources across multiple Availability Zones, use load balancers and auto scaling, deploy databases in Multi-AZ mode, and implement monitoring and backups.

---

## How do you ensure an application remains highly available during infrastructure failures?

### Methods

* Multi-AZ deployment
* Health checks
* Automatic failover
* Load balancing
* Backup strategies

### Strong Interview Answer

Applications remain available during failures by using redundancy across Availability Zones, health checks to detect failures, and automatic failover mechanisms to redirect traffic.

---

## How does cross-region replication support high availability?

### Explanation

Data is copied to another AWS region.

If one region fails → another region continues service.

### Example

S3 Cross-Region Replication
DynamoDB Global Tables

### Strong Interview Answer

Cross-region replication copies data across multiple regions to protect against regional failures and improve disaster recovery capabilities.

---

## What happens when one Availability Zone fails?

### Expected Behavior

If system designed properly:

1. Load balancer stops routing to failed AZ
2. Traffic shifts to healthy AZ
3. Auto Scaling launches new instances

System continues running.

### Strong Interview Answer

When one Availability Zone fails, traffic is automatically redirected to healthy zones. Auto Scaling replaces failed instances, ensuring minimal downtime.

---

## Why is failure isolation important in distributed systems?

### Explanation

Failure isolation prevents one failure from affecting the entire system.

### Example

If one AZ fails → others continue.

Without isolation → full outage.

### Strong Interview Answer

Failure isolation ensures that failures remain limited to specific components, preventing system-wide outages and improving system resilience.

---

## How do Availability Zones ensure high availability?

### Mechanism

* Physically separate data centers
* Independent power/network
* Low-latency connections

### Strong Interview Answer

Availability Zones provide isolated infrastructure that prevents failures from spreading, allowing applications to continue running in other zones.

---

## What is high availability, and how is it achieved in AWS?

### Definition

High availability means the system stays operational with minimal downtime.

### Achieved Using

* Multi-AZ deployment
* Load balancing
* Auto scaling
* Backup strategies

### Strong Interview Answer

High availability means maintaining system uptime despite failures. In AWS, it is achieved using Multi-AZ deployments, load balancing, and automatic failover strategies.

---

## What are SLA and SLO in cloud environments?

### Comparison Table

| Term | Meaning                 | Focus                       |
| ---- | ----------------------- | --------------------------- |
| SLA  | Service Level Agreement | Contract with provider      |
| SLO  | Service Level Objective | Internal performance target |

---

### Example

| Metric | Value                   |
| ------ | ----------------------- |
| SLA    | 99.99% uptime guarantee |
| SLO    | Maintain 99.95% uptime  |

---

### Strong Interview Answer

An SLA is a formal agreement defining service guarantees between provider and customer. An SLO is an internal performance target used to measure service reliability.
