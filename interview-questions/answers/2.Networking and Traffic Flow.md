# 2.1 VPC Fundamentals

## What is a VPC, and why is it needed?

**Interview Answer**

A **VPC (Virtual Private Cloud)** is a logically isolated network inside AWS where you launch resources like EC2, databases, and load balancers.

It is needed to:

* Control **IP addressing**
* Isolate resources from other customers
* Control **inbound and outbound traffic**
* Design **secure and scalable architectures**

**Real Interview Example**

A typical production system:

* Public subnet → Load Balancer
* Private subnet → Application servers
* Private subnet → Database

All inside one VPC.

---

## What are the core components of a VPC, and how do they work together?

**Core Components**

| Component                  | Purpose                               | How It Works                      |
| -------------------------- | ------------------------------------- | --------------------------------- |
| **Subnets**                | Divide VPC into smaller networks      | Separate public/private resources |
| **Route Tables**           | Control traffic direction             | Define where traffic goes         |
| **Internet Gateway (IGW)** | Internet access                       | Allows public subnet access       |
| **NAT Gateway**            | Outbound internet from private subnet | Private instances access internet |
| **Security Groups**        | Instance-level firewall               | Controls allowed traffic          |
| **Network ACL (NACL)**     | Subnet-level firewall                 | Additional security layer         |

**How They Work Together**

Traffic Flow Example:

```
Internet
   ↓
IGW
   ↓
Public Subnet
   ↓
Load Balancer
   ↓
Private Subnet
   ↓
Database
```

---

## What is the default VPC, and what happens if you don't create one?

**Interview Answer**

A **Default VPC** is automatically created in each region.

It includes:

* Public subnets
* Internet Gateway
* Default route tables
* Security groups

**If you don't create your own VPC:**

AWS automatically uses the **default VPC**.

**Important Interview Insight**

In production:

➡ Most companies **do NOT use default VPC**
➡ They create **custom VPCs** for better control.

---

## What is the difference between public and private subnets?

| Feature          | Public Subnet               | Private Subnet               |
| ---------------- | --------------------------- | ---------------------------- |
| Internet Access  | Direct                      | No direct access             |
| Internet Gateway | Required                    | Not used directly            |
| NAT Gateway      | Not needed                  | Needed for outbound internet |
| Typical Usage    | Load balancer, Bastion host | App servers, Databases       |

**Interview Tip**

Public vs Private is defined by:

➡ **Route Table**, not subnet itself.

---

## How does traffic flow from an internet user to backend services inside a VPC?

**Step-by-Step Flow**

```
User Browser
      ↓
Route 53 (DNS)
      ↓
Internet Gateway
      ↓
Public Subnet
      ↓
Load Balancer
      ↓
Private Subnet (App Servers)
      ↓
Database
```

**Interview Insight**

Backend servers remain **private**, increasing security.

---

## What is the role of route tables?

**Interview Answer**

Route tables determine:

➡ Where network traffic is sent.

They contain:

```
Destination → Target
```

Example:

```
0.0.0.0/0 → Internet Gateway
10.0.1.0/24 → Local
```

**Important Insight**

Every subnet must be associated with **one route table**.

# 2.2 Connectivity and Routing

---

## IGW vs NAT Gateway

| Feature          | Internet Gateway (IGW) | NAT Gateway       |
| ---------------- | ---------------------- | ----------------- |
| Purpose          | Internet access        | Outbound internet |
| Used By          | Public subnet          | Private subnet    |
| Inbound Traffic  | Allowed                | Not allowed       |
| Outbound Traffic | Allowed                | Allowed           |
| Public IP Needed | Yes                    | Yes               |

**When to Use**

* IGW → Public-facing resources
* NAT → Private resources needing updates

---

## Elastic IP vs Public IP vs Private IP

| Feature            | Elastic IP          | Public IP               | Private IP             |
| ------------------ | ------------------- | ----------------------- | ---------------------- |
| Scope              | Static              | Dynamic                 | Internal               |
| Internet Reachable | Yes                 | Yes                     | No                     |
| Persistence        | Permanent           | Changes                 | Permanent              |
| Use Case           | NAT, Load balancers | Temporary public access | Internal communication |

---

## VPC Peering vs Transit Gateway

| Feature      | VPC Peering | Transit Gateway          |
| ------------ | ----------- | ------------------------ |
| Connectivity | VPC to VPC  | Many VPCs                |
| Scalability  | Low         | High                     |
| Complexity   | Simple      | Centralized              |
| Routing      | Manual      | Managed                  |
| Use Case     | Few VPCs    | Large enterprise network |

**Interview Rule**

* Few VPCs → Peering
* Many VPCs → Transit Gateway

---

## What is AWS PrivateLink?

**Interview Answer**

**PrivateLink** allows private access to AWS services **without using internet or peering**.

**When to Use**

* Secure service-to-service communication
* Access SaaS privately
* Avoid exposing traffic to internet

---

## What is AWS Direct Connect?

**Interview Answer**

**Direct Connect** is a **dedicated private connection** between on-premise data center and AWS.

**Use Cases**

* Hybrid cloud
* High bandwidth
* Low latency
* Predictable network performance

---

## Direct Connect vs VPN

| Feature     | Direct Connect | VPN                |
| ----------- | -------------- | ------------------ |
| Connection  | Dedicated      | Internet           |
| Speed       | High           | Moderate           |
| Latency     | Low            | Higher             |
| Cost        | Expensive      | Cheaper            |
| Reliability | Very high      | Internet dependent |

# 2.3 DNS and Load Balancing

---

## What is Amazon Route 53?

**Interview Answer**

Amazon Route 53 is a **DNS service** that routes users to applications.

It provides:

* Domain registration
* DNS resolution
* Health checks
* Traffic routing

---

## Route 53 Routing Policies

| Policy        | Purpose                |
| ------------- | ---------------------- |
| Simple        | Single resource        |
| Weighted      | Split traffic          |
| Latency       | Lowest latency         |
| Failover      | Disaster recovery      |
| Geolocation   | Location-based routing |
| **Proximity** | Closest AWS region     |

---

## What happens if Route 53 fails?

**Interview Answer**

Route 53 is **highly available**.

Failover happens using:

* Health checks
* Secondary region routing

Example:

```
Primary region fails
        ↓
Health check fails
        ↓
Route 53 redirects to backup region
```

---

## What is a Load Balancer in AWS?

**Interview Answer**

A **Load Balancer** distributes incoming traffic across multiple servers.

Types:

| Load Balancer | Layer    | Use Case             |
| ------------- | -------- | -------------------- |
| ALB           | Layer 7  | Web apps             |
| NLB           | Layer 4  | High performance     |
| CLB           | Legacy   | Old systems          |
| GWLB          | Security | Firewall integration |

---

## ALB vs NLB

| Feature     | ALB           | NLB          |
| ----------- | ------------- | ------------ |
| OSI Layer   | 7             | 4            |
| Protocol    | HTTP/HTTPS    | TCP/UDP      |
| Routing     | Path-based    | Port-based   |
| Performance | Medium        | Very High    |
| Use Case    | Microservices | High traffic |

---

## How does an Application Load Balancer route traffic?

**Interview Answer**

ALB routes traffic using:

* URL path
* Host header
* HTTP headers

Example:

```
/users → User Service
/orders → Order Service
```

Used heavily in **microservices**.

---

## How does SSL termination work?

**Interview Answer**

SSL termination happens at the load balancer.

Flow:

```
User HTTPS Request
       ↓
Load Balancer decrypts SSL
       ↓
Forward HTTP to backend
```

Benefits:

* Reduces backend CPU load
* Central certificate management

# 2.4 Network Security

---

## Security Groups vs NACLs

| Feature    | Security Group     | NACL               |
| ---------- | ------------------ | ------------------ |
| Level      | Instance           | Subnet             |
| Stateful   | Yes                | No                 |
| Rules      | Allow only         | Allow + Deny       |
| Direction  | Inbound + Outbound | Both               |
| Evaluation | All rules          | Rule order matters |

**How They Work Together**

```
Traffic → NACL → Security Group → Instance
```

---

## How do you design production-ready network security?

**Multi-layer Security Model**

1. VPC Isolation
2. Subnet Separation
3. Security Groups
4. NACLs
5. IAM Policies
6. Encryption
7. Monitoring (logs)

**Architecture Example**

```
Internet
   ↓
WAF
   ↓
Load Balancer
   ↓
Private Subnet
   ↓
Database
```

---

## How do inbound rules, outbound rules, firewalls, and routing work together?

**Interview Answer**

Traffic must pass:

1. Route Table
2. NACL
3. Security Group
4. Application Firewall

If blocked anywhere → Traffic fails.

# 2.5 Secure Service Communication

---

## How does an application securely communicate with S3 or SQS?

Using IAM Roles.

Flow:

```
EC2 Instance
     ↓
IAM Role attached
     ↓
Temporary credentials
     ↓
Access S3/SQS securely
```

Important:

No hardcoded passwords.

---

## Best Practices for Least-Privilege Access

**Interview Answer**

Follow these:

1. Grant minimum required permissions
2. Use IAM roles instead of keys
3. Use resource-level permissions
4. Rotate credentials
5. Monitor access logs
6. Use separate roles per service
