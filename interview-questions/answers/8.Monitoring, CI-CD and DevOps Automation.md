

# **8. Monitoring, CI/CD and DevOps Automation (Interview-Focused Answers)**

## **8.1 Monitoring and Observability**

### **Q1. What is Amazon CloudWatch, and what metrics can it monitor?**

**Answer:**

CloudWatch is a **monitoring + observability service** for AWS resources and applications.

**It monitors:**

* **Infrastructure metrics**

  * EC2 → CPU, memory (custom), disk, network
  * RDS → connections, latency
* **Application metrics (custom metrics)**
* **Logs** (via CloudWatch Logs)
* **Events** (via EventBridge integration)

**Key point (interview):**
CloudWatch is not just metrics → it’s **metrics + logs + alarms + dashboards**

---

### **Q2. How do CloudWatch Alarms work?**

**Answer:**

CloudWatch Alarms:

1. Monitor a **metric**
2. Compare against a **threshold**
3. Trigger an **action**

**Flow:**

```
Metric → Condition → Alarm State → Action
```

**States:**

* OK
* ALARM
* INSUFFICIENT_DATA

**Actions:**

* Send SNS notification
* Trigger Auto Scaling
* Invoke Lambda

**Critical insight:**
Alarms are **reactive**, not predictive.

---

### **Q3. Difference between CloudWatch Logs and CloudTrail**

| Feature  | CloudWatch Logs         | AWS CloudTrail             |
| -------- | ----------------------- | -------------------------- |
| Purpose  | Application/System logs | API auditing               |
| Data     | Logs from apps, EC2     | Who did what in AWS        |
| Use case | Debugging               | Security & compliance      |
| Example  | App error logs          | IAM user deleted S3 bucket |

**Interview trap:**
If you say both are for logging → **incorrect**.
CloudTrail = **audit**, CloudWatch = **observability**

---

### **Q4. What is AWS X-Ray and when should it be used?**

**Answer:**

X-Ray is used for **distributed tracing in microservices**.

**It helps to:**

* Track request flow across services
* Identify latency bottlenecks
* Debug service failures

**Use case:**

* Microservices architecture
* Lambda + API Gateway flows

**Key idea:**
CloudWatch = “What happened”
X-Ray = “Where exactly it broke”

---

### **Q5. How do you troubleshoot performance issues using CloudWatch?**

**Strong interview answer (step-by-step):**

1. Check **high-level metrics**

   * CPU, memory, latency

2. Drill into **logs**

   * Errors, exceptions

3. Use **dashboards**

   * Correlate multiple metrics

4. Set **alarms**

   * Identify abnormal patterns

5. Combine with X-Ray (if needed)

**Common mistake:**
Jumping to logs directly without checking metrics → inefficient debugging.

## **8.2 CI/CD Fundamentals**

### **Q6. What is CI/CD, and why is it important?**

**Answer:**

CI/CD =

* **CI (Continuous Integration)** → Frequent code merge + automated testing
* **CD (Continuous Delivery/Deployment)** → Automated release process

**Why important:**

* Faster releases
* Reduced human errors
* Better software quality

**Reality check:**
CI/CD doesn’t guarantee quality → **bad tests = bad pipeline**

---

### **Q7. AWS services used for CI/CD**

**Core services:**

* AWS CodePipeline → Pipeline orchestration
* AWS CodeBuild → Build & test
* AWS CodeDeploy → Deployment

**External commonly used:**

* GitHub Actions

**Insight:**
Many companies prefer GitHub Actions + AWS (not pure AWS stack)

---

## **8.3 Deployment Strategies**

### **Q8. Typical CI/CD pipeline flow in AWS**

**Flow:**

```
Code Commit → Build → Test → Artifact → Deploy → Monitor
```

**Example:**

1. Developer pushes code (GitHub)
2. CodePipeline triggers
3. CodeBuild runs tests
4. Artifact stored (S3)
5. CodeDeploy deploys to EC2/Lambda
6. CloudWatch monitors

---

### **Q9. What is Infrastructure as Code (IaC)?**

**Answer:**

IaC = Managing infrastructure using **code instead of manual setup**

**Benefits:**

* Repeatability
* Version control
* Automation

**Key idea:**
Manual infra = **error-prone**
IaC = **deterministic**

---

### **Q10. Terraform vs CloudFormation**

| Feature     | Terraform           | AWS CloudFormation |
| ----------- | ------------------- | ------------------ |
| Scope       | Multi-cloud         | AWS only           |
| Language    | HCL                 | JSON/YAML          |
| State       | External state file | Managed by AWS     |
| Flexibility | High                | Moderate           |

**Interview insight:**

* Multi-cloud → Terraform
* Deep AWS integration → CloudFormation

---

### **Q11. What is Blue-Green Deployment?**

**Answer:**

Two environments:

* Blue (current)
* Green (new)

**Flow:**

1. Deploy to Green
2. Test
3. Switch traffic

**Advantage:**

* Zero downtime
* Easy rollback

**Tradeoff:**

* Cost (double infrastructure)

---

### **Q12. What is Canary Deployment?**

**Answer:**

Deploy to **small % of users first**, then gradually increase.

**Example:**

* 5% → 25% → 50% → 100%

**Advantage:**

* Reduced risk
* Early failure detection
