

# 10. Cost Optimization

## 1. How do you optimize AWS costs in production environments?

**Answer:**
Cost optimization is about **reducing waste + choosing the right pricing model + continuous monitoring**.

### Core strategies:

### 1. Right-size resources

* Reduce over-provisioned EC2, RDS
* Use metrics from CloudWatch

👉 Common mistake:
People assume “more CPU = safer” → actually wastes money

---

### 2. Use correct pricing models

* On-Demand → flexible, expensive
* Reserved Instances → long-term savings
* Spot Instances → cheapest (but interruptible)

👉 Skeptic view:
Spot is not always safe → bad for critical workloads

---

### 3. Auto Scaling

* Scale out/in based on traffic
* Avoid paying for idle capacity

---

### 4. Turn off unused resources

* Stop idle EC2 instances
* Delete unused EBS volumes, snapshots

👉 Reality:
Most cloud waste = **forgotten resources**

---

### 5. Use serverless where possible

* Lambda, Fargate → pay per use

👉 Counterpoint:
Serverless is NOT always cheaper at scale

---

### 6. Storage optimization

* Move infrequent data to cheaper tiers
* Use lifecycle policies

---

### 7. Monitor continuously

* Use tools like Cost Explorer, Budgets

---

## 2. What is AWS Cost Explorer, and how is it used?

**Answer:**
AWS Cost Explorer is a tool to **visualize and analyze AWS spending over time**.

### What it shows:

* Cost trends (daily, monthly)
* Service-wise cost (EC2, S3, etc.)
* Usage patterns

### How it is used:

* Identify cost spikes
* Find expensive services
* Forecast future costs

👉 Example:
If EC2 cost suddenly increases → investigate scaling issue

---

### Weak understanding alert:

Some think Cost Explorer reduces cost → wrong
👉 It only gives visibility, **you must act**

---

## 3. What are AWS Budgets, and how do they help manage spending?

**Answer:**
AWS Budgets lets you **set spending limits and alerts**.

### Features:

* Set monthly/quarterly budget
* Alerts via email/SNS when threshold crossed
* Track:

  * Cost
  * Usage
  * Reserved Instance utilization

### Example:

* Budget = $1000/month
* Alert at 80% → notification triggered

---

### Critical thinking:

Budgets do NOT stop spending automatically (by default)

👉 Many assume:
“Budget set = safe” → wrong
You must combine with:

* Alerts
* Automation (Lambda to stop resources)

---

## 4. What strategies help reduce S3 storage costs?

**Answer:**

### 1. Use S3 Storage Classes

* Standard → frequent access
* Standard-IA → infrequent
* Glacier → archival

👉 Move data based on access pattern

---

### 2. Lifecycle Policies

* Automatically move or delete objects

Example:

* After 30 days → IA
* After 90 days → Glacier

---

### 3. Delete unused data

* Remove old logs, backups

👉 Hidden cost:
Old logs = silent money drain

---

### 4. Compression

* Store compressed files (gzip, parquet)

---

### 5. Use Intelligent-Tiering

* Automatically moves data between tiers

---

### 6. Reduce data transfer costs

* Use CloudFront (CDN)
* Avoid unnecessary cross-region transfer

---

### 7. Optimize request costs

* Combine small files
* Reduce API calls

👉 Often ignored:
Requests (PUT/GET) also cost money

---

## Final Interview Insight

A strong candidate doesn’t just list tools — they show **decision thinking**:

* Short-term workloads → On-Demand / Fargate
* Predictable workloads → Reserved Instances
* Unreliable workloads → Spot
* Unknown usage → start flexible, then optimize

---

## Deeper Reality Check

Most engineers think:

> “Cost optimization is a one-time task”

That’s wrong.

👉 It is a **continuous process**:

* Monitor → Analyze → Optimize → Repeat
