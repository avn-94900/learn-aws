# 6.1 Database Selection

## 1) What is the difference between **Amazon RDS** and **DynamoDB**, and when should each be used?

### Core Difference

| Feature        | Amazon RDS                           | Amazon DynamoDB                    |
| -------------- | ------------------------------------ | ---------------------------------- |
| Database Type  | Relational (SQL)                     | NoSQL (Key-Value / Document)       |
| Schema         | Fixed schema (tables, rows, columns) | Flexible schema                    |
| Query Language | SQL                                  | API-based queries                  |
| Scaling        | Vertical + Read Replicas             | Automatic horizontal scaling       |
| Transactions   | Strong relational transactions       | Limited transactional support      |
| Performance    | Good, depends on instance size       | Very fast, single-digit ms latency |
| Use Case       | Structured data                      | Massive scale, low latency         |

---

### When to Use RDS

Use **Amazon RDS** when:

* Data has **clear relationships**
* You need **joins**
* You need **ACID transactions**
* Schema is **structured and stable**

Typical examples:

* Banking systems
* ERP systems
* Order management
* Inventory systems

Common engines in RDS:

* MySQL
* PostgreSQL
* Oracle Database
* Microsoft SQL Server

---

### When to Use DynamoDB

Use **Amazon DynamoDB** when:

* You need **very fast response time**
* Traffic is **very high**
* Schema is **flexible**
* No complex joins needed

Typical examples:

* User session storage
* Shopping cart
* Gaming leaderboards
* IoT data storage

---

### Strong Interview Answer

**Amazon RDS is a relational database service used for structured data and SQL queries, while DynamoDB is a NoSQL database designed for high-speed, large-scale workloads. I would use RDS when relationships and transactions are important, and DynamoDB when I need massive scalability and very low latency.**

## 2) What is the difference between **Read Replicas** and **Multi-AZ deployments** in RDS?

This is a very common interview question.

### Core Difference

| Feature   | Read Replica                 | Multi-AZ Deployment      |
| --------- | ---------------------------- | ------------------------ |
| Purpose   | Improve **read performance** | Improve **availability** |
| Data Copy | Asynchronous                 | Synchronous              |
| Failover  | Manual                       | Automatic                |
| Usage     | Scaling reads                | Disaster recovery        |
| Number    | Multiple allowed             | One standby              |

---

### Read Replica

Used for:

* Heavy **read traffic**
* Reporting workloads
* Analytics queries

Flow:

```
Primary DB → Read Replica(s)
             (Read only)
```

Example:

* E-commerce product catalog
* Reporting dashboards

---

### Multi-AZ Deployment

Used for:

* **High availability**
* Automatic failover
* Disaster recovery

Flow:

```
Primary DB ⇄ Standby DB
 (Sync replication)
```

If primary fails → standby becomes primary automatically.

---

### Strong Interview Answer

**Read Replicas are used to scale read traffic by creating read-only copies of the database, while Multi-AZ deployments are used for high availability by maintaining a synchronous standby database that automatically takes over during failure.**

---

## 3) When should you use **DynamoDB** instead of **RDS**?

Use **DynamoDB** when:

### Key Decision Conditions

Choose **DynamoDB** if:

* You need **millions of requests per second**
* Data size is **very large**
* Traffic is **unpredictable**
* You need **low latency (<10 ms)**

Avoid DynamoDB if:

* Complex joins are required
* Complex reporting is needed
* Strong relational consistency required

---

### Real Example

Use **DynamoDB** for:

* Online gaming sessions
* IoT sensor data
* Real-time analytics
* Mobile apps backend

Use **RDS** for:

* Payment systems
* HR systems
* Order processing

---

### Strong Interview Answer

**I use DynamoDB instead of RDS when the application requires very high throughput, low latency, and flexible schema design, and when relational queries or joins are not required.**

## 4) How do you design **highly available database architectures** in AWS?

This is a **system design level** question.

---

### Key Design Techniques

#### 1) Use Multi-AZ Deployment

Most important step.

```
Primary DB (AZ1)
        ⇅
Standby DB (AZ2)
```

If AZ fails → automatic failover.

---

#### 2) Use Read Replicas

Used to:

* Distribute read load
* Improve performance

```
Primary → Replica1
        → Replica2
```

---

#### 3) Enable Automated Backups

Use:

* Snapshots
* Point-in-time recovery

This protects against:

* Data corruption
* Accidental deletion

---

#### 4) Use Connection Pooling

Helps:

* Reduce DB overload
* Improve performance

Tools:

* Amazon RDS Proxy

---

#### 5) Multi-Region Replication (Advanced)

Used for:

* Disaster recovery
* Global apps

Options:

* Cross-region read replicas
* Global tables (for DynamoDB)

Example:

* India Region
* Singapore Region backup

---

### Strong Interview Answer

**To design a highly available database in AWS, I use Multi-AZ deployments for failover, Read Replicas for scaling reads, automated backups for recovery, and cross-region replication for disaster recovery.**

## 5) What are **DynamoDB indexes**, and when are they needed?

Indexes improve **query performance**.

### Types of DynamoDB Indexes

| Index Type | Full Name              | Use Case                               |
| ---------- | ---------------------- | -------------------------------------- |
| LSI        | Local Secondary Index  | Same partition key, different sort key |
| GSI        | Global Secondary Index | Different partition key                |

---

### Local Secondary Index (LSI)

Rules:

* Same partition key
* Different sort key
* Created **during table creation**

Used when:

* Need alternate sorting method

Example:

```
PK = UserID
Sort by:
   OrderDate
   OrderAmount
```

---

### Global Secondary Index (GSI)

Rules:

* Different partition key allowed
* Can be created later

Used when:

* Need completely new query pattern

Example:

```
Original Table:
PK = UserID

GSI:
PK = ProductID
```

---

### When Indexes Are Needed

Use indexes when:

* Query pattern changes
* Need faster lookups
* Need alternate access pattern

---

### Strong Interview Answer

**DynamoDB indexes provide alternate ways to query data efficiently. Local Secondary Indexes use the same partition key with a different sort key, while Global Secondary Indexes allow completely different partition keys and are used to support new query patterns.**

## 6) What are **DynamoDB Streams**, and what use cases require them?

### What is DynamoDB Streams?

Amazon DynamoDB Streams records every change made to a table.

Changes captured:

* INSERT
* MODIFY
* DELETE

---

### How It Works

```
DynamoDB Table
        ↓
DynamoDB Stream
        ↓
Lambda Trigger
```

Often integrated with:

* AWS Lambda

---

### Common Use Cases

#### 1) Real-Time Processing

Example:

* Send notification when order created

```
New Order → Stream → Lambda → Send Email
```

---

#### 2) Data Replication

Used to:

* Copy data to another table
* Sync systems

Example:

```
DynamoDB → Stream → Another Database
```

---

#### 3) Audit Logs

Used to:

* Track data changes
* Maintain history

Example:

```
User Update → Log Entry Created
```

---

#### 4) Event-Driven Systems

Used in:

* Microservices architectures

---

### Strong Interview Answer

**DynamoDB Streams capture real-time changes in a table, including inserts, updates, and deletes. They are commonly used for triggering Lambda functions, building event-driven architectures, maintaining audit logs, and replicating data across systems.**
