

# 9. Containers and Orchestration

## 1. What is Docker, and how is it used in cloud environments?

**Answer:**
Docker is a containerization platform that packages an application with its dependencies into a **container** so it runs consistently across environments.

**In cloud:**

* Build image → push to registry (like ECR)
* Run containers on services like ECS/EKS
* Enables **microservices + portability**

**Key benefit:**

* “Works on my machine” problem disappears

**Challenge your assumption:**

* Many think Docker = lightweight VM → wrong
  → Containers share OS kernel, so they are lighter than VMs

---

## 2. What is Amazon ECS, and how does it work?

**Answer:**
Amazon Elastic Container Service (ECS) is a **fully managed container orchestration service by AWS**.

**How it works:**

* You define:

  * Task Definition (container config)
  * Service (how many containers to run)
* ECS scheduler:

  * Places containers on compute (EC2 or Fargate)
* Integrates with:

  * ALB (load balancing)
  * IAM (security)
  * CloudWatch (monitoring)

**Core components:**

* Cluster
* Task Definition
* Task
* Service

**Reality check:**

* Easier than Kubernetes but **less flexible**
* Strong AWS integration = vendor lock-in risk

---

## 3. What is Amazon EKS, and how does it work?

**Answer:**
Amazon Elastic Kubernetes Service (EKS) is AWS’s **managed Kubernetes service**.

It runs standard Kubernetes.

**How it works:**

* AWS manages:

  * Control plane (API server, etcd)
* You manage:

  * Worker nodes (EC2 or Fargate)
* You deploy using:

  * Pods
  * Deployments
  * Services

**Key advantage:**

* Uses **industry-standard Kubernetes**

**Challenge your thinking:**

* EKS is not “fully managed”
  → You still manage nodes, scaling, networking complexity

---

## 4. Difference between Amazon ECS and Amazon EKS

| Feature          | ECS         | EKS               |
| ---------------- | ----------- | ----------------- |
| Type             | AWS-native  | Kubernetes-based  |
| Learning curve   | Easy        | Steep             |
| Flexibility      | Limited     | Very high         |
| Portability      | Low         | High              |
| Setup complexity | Simple      | Complex           |
| Control          | AWS-managed | More user control |

**Simple way to say in interview:**

* ECS = **simple + AWS tightly integrated**
* EKS = **powerful + industry standard**

**Critical thinking:**

* Many assume EKS is always better → wrong
  → If team doesn’t know Kubernetes, it slows you down

## 5. What is AWS Fargate, and when should it be used?

**Answer:**
AWS Fargate is a **serverless compute engine for containers**.

**Meaning:**

* No need to manage servers (no EC2)
* Just run containers

**When to use:**

* No infra management needed
* Small/medium workloads
* Variable traffic
* Microservices

**Benefits:**

* Auto scaling
* Pay per use
* Simpler operations

**Hidden trade-off:**

* Less control
* Can be **more expensive** than EC2 at scale

---

## 6. When should you use EC2 launch type vs Fargate?

### Use EC2 when:

* You want **full control** of infrastructure
* Running **large, steady workloads**
* Need **GPU / special hardware**
* Cost optimization at scale

### Use Fargate when:

* You want **no server management**
* Workloads are **sporadic or unpredictable**
* Faster setup needed
* Small teams / startups

---

## Interview Insight (Important)

A strong answer is not just definitions — it shows decision thinking:

* If simplicity → ECS + Fargate
* If control + portability → EKS
* If cost optimization at scale → ECS/EKS + EC2
