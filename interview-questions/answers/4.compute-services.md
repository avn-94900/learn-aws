

## 4. Compute Services

## 4.1 EC2 and Compute Models

### Q1. What are the different EC2 pricing models (On-Demand, Reserved, Spot)?

| Pricing Model                                  | Description                                         | When to Use                         | Key Benefit                   | Risk / Limitation             |
| ---------------------------------------------- | --------------------------------------------------- | ----------------------------------- | ----------------------------- | ----------------------------- |
| **On-Demand Instances**                        | Pay per second/hour with no long-term commitment    | Short-term, unpredictable workloads | Flexible and simple           | Most expensive option         |
| **Reserved Instances (RI)**                    | Commit to 1 or 3 years for discounted pricing       | Steady, predictable workloads       | Up to ~70% cost savings       | Requires long-term commitment |
| **Spot Instances**                             | Use unused AWS capacity at very low cost            | Fault-tolerant workloads            | Up to ~90% cheaper            | Can be terminated anytime     |
| **Savings Plans** *(modern alternative to RI)* | Commit to usage amount instead of specific instance | Flexible long-term workloads        | Cost savings with flexibility | Still requires commitment     |

**Strong Interview Answer:**
EC2 provides multiple pricing models: On-Demand for flexible short-term use, Reserved Instances or Savings Plans for predictable long-term workloads, and Spot Instances for fault-tolerant workloads where interruptions are acceptable.

---

### Q2. When should you choose Spot Instances, and what are typical use cases?

##### Choose Spot Instances when:

* Application can handle interruption
* Workload is stateless
* You want very low cost

##### Typical Use Cases:

* Batch processing
* Big data analytics
* CI/CD pipelines
* Image/video rendering
* Machine learning training
* Stateless microservices

**Strong Interview Answer:**
Spot Instances should be used when workloads are fault-tolerant and can recover from interruptions. Typical use cases include batch jobs, data processing, CI/CD tasks, and machine learning workloads.

### Q3. What are the different ways to connect to an EC2 instance, and when should each be used?

| Connection Method                       | Used For                              | Typical Scenario                      |
| --------------------------------------- | ------------------------------------- | ------------------------------------- |
| **SSH**                                 | Linux instances                       | Direct admin access                   |
| **RDP**                                 | Windows instances                     | Windows GUI access                    |
| **EC2 Instance Connect**                | Browser-based SSH                     | Quick secure access without key setup |
| **AWS Systems Manager Session Manager** | Secure shell access without SSH ports | Secure production environments        |
| **Bastion Host**                        | Controlled external access            | Private subnet access                 |
| **VPN / Direct Connect**                | Corporate network access              | Hybrid architecture                   |

**Strong Interview Answer:**
EC2 instances can be accessed using SSH for Linux, RDP for Windows, Session Manager for secure access without opening ports, and Bastion hosts or VPNs when accessing instances in private subnets.

## 4.2 Serverless and Event-Driven

---

### Q4. What are Lambda triggers, and how do they enable event-driven architectures?

**Lambda triggers** are AWS services that automatically invoke a Lambda function when an event occurs.

##### Common Lambda Triggers:

* **S3** → File upload
* **API Gateway** → HTTP request
* **DynamoDB Streams** → Data change
* **SQS** → Message arrival
* **SNS** → Notification event
* **CloudWatch Events / EventBridge** → Scheduled jobs

##### How this enables event-driven architecture:

Instead of polling systems, events automatically trigger processing.

**Example Flow:**

```
User uploads file → S3 event → Lambda triggered → Process file
```

**Strong Interview Answer:**
Lambda triggers are events generated by AWS services that automatically invoke Lambda functions, enabling event-driven architectures where applications react to events instead of continuously polling resources.

---

### Q5. What is serverless computing, and how does it differ from traditional compute models?

| Feature                   | Serverless        | Traditional (EC2)                |
| ------------------------- | ----------------- | -------------------------------- |
| Infrastructure management | AWS manages       | You manage                       |
| Scaling                   | Automatic         | Manual or Auto Scaling           |
| Billing                   | Pay per execution | Pay per running instance         |
| Maintenance               | Minimal           | Requires patching and monitoring |
| Startup time              | Fast              | Depends on instance              |

**Strong Interview Answer:**
Serverless computing allows developers to run code without managing servers. AWS handles scaling, patching, and infrastructure, while billing is based only on execution time instead of instance uptime.

---

### Q6. What are the benefits of serverless architecture?

##### Key Benefits:

1. No server management
2. Automatic scaling
3. Pay-per-use pricing
4. Faster development
5. High availability built-in
6. Reduced operational overhead

**Strong Interview Answer:**
Serverless architecture reduces operational overhead by eliminating server management, provides automatic scaling, supports pay-per-use billing, and enables faster application development.

### Q7. What are the limitations of AWS Lambda?

##### Major Limitations:

| Limitation              | Details                                     |
| ----------------------- | ------------------------------------------- |
| Execution Timeout       | Max **15 minutes**                          |
| Cold Start Latency      | Delay when function starts after inactivity |
| Memory Limits           | Max **10 GB** memory                        |
| Deployment Package Size | Size restrictions                           |
| Stateless Nature        | No persistent memory                        |
| Concurrency Limits      | Account-level limits apply                  |

##### Real-world impact:

* Not suitable for long-running jobs
* Not ideal for heavy compute workloads

**Strong Interview Answer:**
AWS Lambda has limitations such as a maximum execution time of 15 minutes, cold start latency, memory limits, and stateless execution, making it unsuitable for long-running or high-performance computing workloads.

### Q8. What is AWS API Gateway, and how does it integrate with Lambda?

**AWS API Gateway** is a managed service used to create, publish, and secure APIs.

##### How Integration Works:

```
Client → API Gateway → Lambda → Response
```

##### Key Roles:

| Component   | Responsibility        |
| ----------- | --------------------- |
| API Gateway | Receives HTTP request |
| Lambda      | Processes request     |
| API Gateway | Returns response      |

##### Features:

* Authentication (IAM, Cognito)
* Rate limiting
* Request validation
* Logging
* HTTPS support

**Strong Interview Answer:**
API Gateway is used to create REST APIs that trigger Lambda functions. It acts as the front door for applications, handling HTTP requests, authentication, throttling, and routing requests to backend Lambda functions.

---

### Q9. How do you design and build a serverless REST API using AWS services?

##### Typical Architecture:

```
Client
   ↓
API Gateway
   ↓
Lambda Function
   ↓
DynamoDB
```

##### Step-by-step design:

1. Create API in **API Gateway**
2. Define REST endpoints (GET, POST, PUT)
3. Connect endpoints to **Lambda**
4. Write Lambda logic
5. Store data in **DynamoDB**
6. Enable authentication
7. Deploy API

---

##### Common Production Enhancements:

* Use **Lambda Layers**
* Enable **CloudWatch logging**
* Use **API throttling**
* Enable **IAM or Cognito authentication**
* Add **DynamoDB indexes**

---

**Strong Interview Answer:**
A serverless REST API can be built using API Gateway to expose HTTP endpoints, Lambda to process requests, and DynamoDB to store data. API Gateway routes requests to Lambda functions, which execute business logic and interact with storage services.
