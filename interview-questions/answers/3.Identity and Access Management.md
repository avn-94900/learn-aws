
# 3. Identity and Access Management (IAM)

## 3.1 IAM Fundamentals

## What is IAM, and why is it critical for AWS security?

**Short Explanation:**
**IAM (Identity and Access Management)** is a service in Amazon Web Services that controls **who can access what resources** and **what actions they can perform**.

**Strong Interview Answer:**
IAM is used to manage authentication and authorization in AWS. It allows you to create users, groups, and roles, and assign permissions using policies. It is critical because it enforces **least-privilege access**, protects resources from unauthorized access, and provides centralized security control across AWS services.

**Key Points to Mention in Interview:**

* Controls **authentication** (who you are)
* Controls **authorization** (what you can do)
* Supports **least privilege principle**
* Enables **secure access to AWS resources**

---

## What is the difference between IAM Roles and IAM Policies?

This is a **very common interview question**.

| Feature     | IAM Role                         | IAM Policy                                 |
| ----------- | -------------------------------- | ------------------------------------------ |
| Definition  | An identity that can be assumed  | A document that defines permissions        |
| Purpose     | Provides temporary permissions   | Defines what actions are allowed or denied |
| Contains    | Trust policy + permission policy | JSON permission rules                      |
| Used By     | Users, services, applications    | Attached to users, groups, or roles        |
| Credentials | Temporary credentials            | No credentials                             |
| Example     | EC2 accessing S3                 | Allow `s3:GetObject`                       |

**Strong Interview Answer:**
An IAM Role is an identity that can be assumed to gain temporary permissions, while an IAM Policy is a JSON document that defines the permissions granted to users, groups, or roles. Roles use policies to determine what actions are allowed.

---

## What are the different types of IAM policies, and when should each be used?

### Types of IAM Policies

| Policy Type                 | Description                         | When to Use                                   |
| --------------------------- | ----------------------------------- | --------------------------------------------- |
| **Identity-Based Policy**   | Attached to users, groups, or roles | To control permissions for identities         |
| **Resource-Based Policy**   | Attached to resources               | When external access to resources is needed   |
| **Inline Policy**           | Embedded directly into identity     | When strict one-to-one permissions are needed |
| **Managed Policy**          | Reusable standalone policy          | When permissions must be reused               |
| **AWS Managed Policy**      | Predefined by AWS                   | Quick setup or standard permissions           |
| **Customer Managed Policy** | Created by user                     | Custom security control                       |

**Strong Interview Answer:**
IAM policies define permissions in AWS. Identity-based policies control permissions for users, groups, or roles, while resource-based policies are attached directly to resources like S3 buckets. Managed policies are reusable, whereas inline policies are tightly bound to a single identity.

---

## What are the different types of IAM roles, and where are they commonly used?

### IAM Role Types

| Role Type                 | Where Used                  | Example                        |
| ------------------------- | --------------------------- | ------------------------------ |
| **Service Role**          | AWS services                | EC2 accessing S3               |
| **Cross-Account Role**    | Multiple AWS accounts       | Account A accessing Account B  |
| **Federated Role**        | External identity providers | Company login using SAML       |
| **EC2 Instance Role**     | EC2 instances               | Application accessing DynamoDB |
| **Lambda Execution Role** | Lambda functions            | Lambda writing logs            |

**Strong Interview Answer:**
IAM roles provide temporary access permissions. Common role types include service roles used by AWS services, cross-account roles for sharing access between accounts, and federated roles used for external authentication systems.

---

## What is a service principal in IAM?

**Short Explanation:**
A **service principal** identifies an AWS service that is allowed to assume a role.

**Example:**

```
ec2.amazonaws.com
lambda.amazonaws.com
```

**Strong Interview Answer:**
A service principal is the AWS service that is trusted to assume an IAM role. It is defined in the trust policy and specifies which service is allowed to use the role.

# 3.2 Secrets and Authentication

---

## What is AWS Secrets Manager, and why should it be used instead of storing credentials in code?

Refers to: AWS Secrets Manager

### What It Is

AWS Secrets Manager securely stores:

* Database credentials
* API keys
* Tokens
* Passwords

---

### Why Not Store Credentials in Code?

| Storing in Code             | Using Secrets Manager        |
| --------------------------- | ---------------------------- |
| Hard to rotate credentials  | Automatic rotation supported |
| Security risk if code leaks | Encrypted storage            |
| No access control           | IAM-based access control     |
| Difficult auditing          | Full audit logging           |

---

**Strong Interview Answer:**
AWS Secrets Manager is used to securely store and manage sensitive credentials such as database passwords and API keys. It should be used instead of storing credentials in code because it supports encryption, automatic rotation, secure access using IAM, and audit logging.

---

## How do you implement Multi-Factor Authentication (MFA) in AWS?

**Short Explanation:**
MFA adds an extra security layer by requiring **two forms of authentication**.

Usually:

1. Password
2. OTP from device

---

### Steps to Enable MFA

1. Open IAM console
2. Select user
3. Enable MFA
4. Attach MFA device:

Types:

* Virtual MFA (mobile app)
* Hardware MFA device

Common apps:

* Google Authenticator
* Microsoft Authenticator

---

**Strong Interview Answer:**
Multi-Factor Authentication is implemented by enabling an MFA device for IAM users or root users. It requires users to provide both a password and a one-time authentication code, significantly improving security against credential theft.

---

## How do you implement secure authentication for applications running on AWS?

This is a **design-level interview question**.

### Recommended Secure Authentication Methods

| Method                     | Use Case                        | Why Secure                 |
| -------------------------- | ------------------------------- | -------------------------- |
| **IAM Roles**              | EC2, Lambda access AWS services | No credentials stored      |
| **AWS Cognito**            | User authentication             | Managed identity service   |
| **Secrets Manager**        | Store credentials               | Secure storage             |
| **Federation (SAML/OIDC)** | Enterprise login                | External identity provider |
| **MFA**                    | User authentication             | Extra security layer       |

Includes:
Amazon Cognito

---

### Typical Secure Architecture Example

For an application running on EC2:

1. Assign **IAM Role** to EC2
2. Store DB credentials in **Secrets Manager**
3. Use **MFA** for user access
4. Use **Cognito** for user login

---

**Strong Interview Answer:**
Secure authentication for applications in AWS is implemented using IAM roles instead of hardcoded credentials, storing secrets in Secrets Manager, and using services like Amazon Cognito or federated identity providers for user authentication. MFA should also be enabled for sensitive access.
