# SQS Security & Access Control - Interview Answers

## 1. Implementing Security for SQS Queues using IAM Policies

**Answer:**

IAM policies control access to SQS queues by defining who can perform what actions on which resources. There are two main approaches:

### Identity-Based Policies (Attached to Users/Roles)

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "sqs:SendMessage",
                "sqs:ReceiveMessage",
                "sqs:DeleteMessage",
                "sqs:GetQueueAttributes"
            ],
            "Resource": "arn:aws:sqs:us-east-1:123456789012:MyQueue"
        }
    ]
}
```

### Least Privilege Principle Implementation

**Producer Role Policy:**
```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "sqs:SendMessage",
                "sqs:GetQueueUrl"
            ],
            "Resource": "arn:aws:sqs:*:*:orders-*"
        }
    ]
}
```

**Consumer Role Policy:**
```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "sqs:ReceiveMessage",
                "sqs:DeleteMessage",
                "sqs:ChangeMessageVisibility"
            ],
            "Resource": "arn:aws:sqs:*:*:orders-*",
            "Condition": {
                "StringEquals": {
                    "aws:RequestedRegion": "us-east-1"
                }
            }
        }
    ]
}
```

### Spring Boot Java Implementation

```java
@Configuration
public class SQSConfig {
    
    @Bean
    public AmazonSQSAsync amazonSQSAsync() {
        return AmazonSQSAsyncClientBuilder.standard()
            .withCredentials(DefaultAWSCredentialsProviderChain.getInstance())
            .withRegion(Regions.US_EAST_1)
            .build();
    }
    
    @Bean
    public QueueMessagingTemplate queueMessagingTemplate() {
        return new QueueMessagingTemplate(amazonSQSAsync());
    }
}
```

## 2. SQS Resource-Based Policy vs IAM Policies

**Answer:**

### Resource-Based Policies (Queue Policies)
- Attached directly to the SQS queue
- Define who can access the queue from outside your account
- JSON document stored as queue attribute
- Maximum size: 8,192 characters

### Key Differences:

| Aspect | IAM Policies | Resource-Based Policies |
|--------|--------------|------------------------|
| **Attachment** | Users, groups, roles | SQS queue directly |
| **Scope** | Account-wide permissions | Queue-specific permissions |
| **Cross-Account** | Requires trust relationships | Direct external access |
| **Evaluation** | Union of all applicable policies | Combined with IAM policies |

### Resource-Based Policy Example

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "AllowCrossAccountAccess",
            "Effect": "Allow",
            "Principal": {
                "AWS": "arn:aws:iam::555666777888:root"
            },
            "Action": "sqs:SendMessage",
            "Resource": "arn:aws:sqs:us-east-1:123456789012:MyQueue",
            "Condition": {
                "StringEquals": {
                    "aws:SourceAccount": "555666777888"
                }
            }
        }
    ]
}
```

### Spring Boot Implementation

```java
@Service
public class QueuePolicyService {
    
    @Autowired
    private AmazonSQS amazonSQS;
    
    public void setQueuePolicy(String queueUrl, String policyDocument) {
        Map<String, String> attributes = new HashMap<>();
        attributes.put(QueueAttributeName.Policy.toString(), policyDocument);
        
        SetQueueAttributesRequest request = new SetQueueAttributesRequest()
            .withQueueUrl(queueUrl)
            .withAttributes(attributes);
            
        amazonSQS.setQueueAttributes(request);
    }
}
```

## 3. Implementing Cross-Account Access for SQS Queues

**Answer:**

Cross-account access allows SQS queues in one AWS account to be accessed by principals in another account.

### Implementation Steps:

**Step 1: Resource-Based Policy on Queue (Account A)**
```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "CrossAccountAccess",
            "Effect": "Allow",
            "Principal": {
                "AWS": [
                    "arn:aws:iam::ACCOUNT-B:role/SQSConsumerRole",
                    "arn:aws:iam::ACCOUNT-B:user/ServiceUser"
                ]
            },
            "Action": [
                "sqs:ReceiveMessage",
                "sqs:DeleteMessage"
            ],
            "Resource": "arn:aws:sqs:us-east-1:ACCOUNT-A:CrossAccountQueue"
        }
    ]
}
```

**Step 2: IAM Policy in Account B**
```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "sqs:ReceiveMessage",
                "sqs:DeleteMessage"
            ],
            "Resource": "arn:aws:sqs:us-east-1:ACCOUNT-A:CrossAccountQueue"
        }
    ]
}
```

### Spring Boot Cross-Account Implementation

```java
@Configuration
public class CrossAccountSQSConfig {
    
    @Value("${aws.cross.account.queue.url}")
    private String crossAccountQueueUrl;
    
    @Bean
    @Qualifier("crossAccountSQS")
    public AmazonSQS crossAccountSQS() {
        // Assume role in Account B to access Account A's queue
        STSAssumeRoleSessionCredentialsProvider credentialsProvider = 
            new STSAssumeRoleSessionCredentialsProvider.Builder(
                "arn:aws:iam::ACCOUNT-B:role/SQSCrossAccountRole",
                "CrossAccountSession"
            ).build();
            
        return AmazonSQSClientBuilder.standard()
            .withCredentials(credentialsProvider)
            .withRegion(Regions.US_EAST_1)
            .build();
    }
}

@Service
public class CrossAccountMessageService {
    
    @Autowired
    @Qualifier("crossAccountSQS")
    private AmazonSQS crossAccountSQS;
    
    public void receiveFromCrossAccountQueue(String queueUrl) {
        ReceiveMessageRequest request = new ReceiveMessageRequest()
            .withQueueUrl(queueUrl)
            .withMaxNumberOfMessages(10)
            .withWaitTimeSeconds(20);
            
        ReceiveMessageResult result = crossAccountSQS.receiveMessage(request);
        // Process messages
    }
}
```

## 4. Encryption Options Available in SQS

**Answer:**

SQS provides multiple encryption options to protect messages at rest and in transit.

### Server-Side Encryption (SSE) Options:

**1. SSE-SQS (SQS-Managed Keys)**
- Default encryption using SQS-managed keys
- No additional configuration required
- Automatic key rotation

**2. SSE-KMS (Customer Managed Keys)**
- Uses AWS KMS Customer Master Keys (CMKs)
- Fine-grained access control
- Audit trail through CloudTrail

**3. SSE-KMS (AWS Managed Keys)**
- Uses AWS-managed KMS keys
- No key management overhead
- Still provides KMS audit capabilities

### Configuration Examples:

**Creating Encrypted Queue:**
```java
@Service
public class EncryptedQueueService {
    
    @Autowired
    private AmazonSQS amazonSQS;
    
    public String createEncryptedQueue(String queueName, String kmsKeyId) {
        Map<String, String> attributes = new HashMap<>();
        attributes.put(QueueAttributeName.KmsMasterKeyId.toString(), kmsKeyId);
        attributes.put(QueueAttributeName.KmsDataKeyReusePeriodSeconds.toString(), "300");
        
        CreateQueueRequest request = new CreateQueueRequest()
            .withQueueName(queueName)
            .withAttributes(attributes);
            
        CreateQueueResult result = amazonSQS.createQueue(request);
        return result.getQueueUrl();
    }
}
```

### Spring Boot Configuration:

```java
@Configuration
public class EncryptedSQSConfig {
    
    @Value("${aws.kms.key.id}")
    private String kmsKeyId;
    
    @Bean
    public QueueMessagingTemplate encryptedQueueTemplate() {
        AmazonSQSAsync sqsAsync = AmazonSQSAsyncClientBuilder.standard()
            .withRegion(Regions.US_EAST_1)
            .build();
            
        return new QueueMessagingTemplate(sqsAsync);
    }
}
```

## 5. Implementing Message-Level Encryption in SQS

**Answer:**

Message-level encryption provides additional security by encrypting message content before sending to SQS, independent of SQS server-side encryption.

### Implementation Approaches:

**1. Client-Side Encryption using AWS Encryption SDK:**

```java
@Service
public class MessageEncryptionService {
    
    private final AwsCrypto crypto = new AwsCrypto();
    private final KmsMasterKeyProvider keyProvider;
    
    public MessageEncryptionService(@Value("${aws.kms.key.arn}") String kmsKeyArn) {
        this.keyProvider = KmsMasterKeyProvider.builder()
            .buildStrict(kmsKeyArn);
    }
    
    public String encryptMessage(String plaintext) {
        CryptoResult<String, KmsMasterKey> encryptResult = crypto.encryptString(
            keyProvider, plaintext);
        return encryptResult.getResult();
    }
    
    public String decryptMessage(String ciphertext) {
        CryptoResult<String, KmsMasterKey> decryptResult = crypto.decryptString(
            keyProvider, ciphertext);
        return decryptResult.getResult();
    }
}
```

**2. Custom Encryption Service:**

```java
@Component
public class CustomMessageEncryption {
    
    private final AESUtil aesUtil;
    private final KMSClient kmsClient;
    
    @Autowired
    public CustomMessageEncryption(AESUtil aesUtil, KMSClient kmsClient) {
        this.aesUtil = aesUtil;
        this.kmsClient = kmsClient;
    }
    
    public EncryptedMessage encryptMessage(String message) {
        // Generate data key from KMS
        GenerateDataKeyRequest dataKeyRequest = GenerateDataKeyRequest.builder()
            .keyId("alias/sqs-message-encryption")
            .keySpec(DataKeySpec.AES_256)
            .build();
            
        GenerateDataKeyResponse dataKeyResponse = kmsClient.generateDataKey(dataKeyRequest);
        
        // Encrypt message with data key
        String encryptedMessage = aesUtil.encrypt(message, dataKeyResponse.plaintext().asByteArray());
        
        return EncryptedMessage.builder()
            .encryptedData(encryptedMessage)
            .encryptedDataKey(Base64.getEncoder().encodeToString(
                dataKeyResponse.ciphertextBlob().asByteArray()))
            .build();
    }
    
    public String decryptMessage(EncryptedMessage encryptedMessage) {
        // Decrypt data key
        DecryptRequest decryptRequest = DecryptRequest.builder()
            .ciphertextBlob(SdkBytes.fromByteArray(
                Base64.getDecoder().decode(encryptedMessage.getEncryptedDataKey())))
            .build();
            
        DecryptResponse decryptResponse = kmsClient.decrypt(decryptRequest);
        
        // Decrypt message
        return aesUtil.decrypt(encryptedMessage.getEncryptedData(), 
            decryptResponse.plaintext().asByteArray());
    }
}
```

**3. Integration with SQS Service:**

```java
@Service
public class SecureMessageService {
    
    @Autowired
    private QueueMessagingTemplate queueMessagingTemplate;
    
    @Autowired
    private MessageEncryptionService encryptionService;
    
    public void sendEncryptedMessage(String queueName, Object message) {
        try {
            String jsonMessage = objectMapper.writeValueAsString(message);
            String encryptedMessage = encryptionService.encryptMessage(jsonMessage);
            
            queueMessagingTemplate.convertAndSend(queueName, encryptedMessage);
        } catch (Exception e) {
            throw new MessageEncryptionException("Failed to encrypt and send message", e);
        }
    }
    
    @SqsListener("${queue.secure.name}")
    public void receiveEncryptedMessage(String encryptedMessage) {
        try {
            String decryptedMessage = encryptionService.decryptMessage(encryptedMessage);
            MyMessageType message = objectMapper.readValue(decryptedMessage, MyMessageType.class);
            
            // Process decrypted message
            processMessage(message);
        } catch (Exception e) {
            throw new MessageDecryptionException("Failed to decrypt message", e);
        }
    }
}
```

## 6. VPC Endpoint Considerations for SQS

**Answer:**

VPC endpoints enable private connectivity between your VPC and SQS without internet gateway, NAT, or VPN connections.

### VPC Endpoint Types:

**Interface Endpoints (AWS PrivateLink):**
- Creates ENI in your subnet
- Supports all SQS APIs
- DNS resolution within VPC
- Security groups control access

### Implementation Considerations:

**1. Security Group Configuration:**
```java
// Security group rules for VPC endpoint
{
    "Type": "AWS::EC2::SecurityGroup",
    "Properties": {
        "SecurityGroupIngress": [
            {
                "IpProtocol": "tcp",
                "FromPort": 443,
                "ToPort": 443,
                "SourceSecurityGroupId": "sg-application-tier"
            }
        ]
    }
}
```

**2. Endpoint Policy:**
```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Principal": "*",
            "Action": [
                "sqs:SendMessage",
                "sqs:ReceiveMessage",
                "sqs:DeleteMessage"
            ],
            "Resource": "*",
            "Condition": {
                "StringEquals": {
                    "aws:PrincipalVpc": "vpc-12345678"
                }
            }
        }
    ]
}
```

**3. Spring Boot Configuration for VPC Endpoint:**

```java

}
```

### Best Practices:
- Use DNS resolution for automatic endpoint discovery
- Configure appropriate security groups
- Monitor VPC endpoint usage and costs
- Test connectivity from all subnets

## 7. Implementing Temporary Credentials and Assume Roles with SQS

**Answer:**

Temporary credentials provide secure, time-limited access to AWS resources using AWS STS (Security Token Service).

### Implementation Approaches:

**1. IAM Role Assumption:**

```java
@Configuration
public class STSConfig {
    
    @Bean
    public AWSSecurityTokenService stsClient() {
        return AWSSecurityTokenServiceClientBuilder.standard()
            .withRegion(Regions.US_EAST_1)
            .build();
    }
}

@Service
public class AssumeRoleService {
    
    @Autowired
    private AWSSecurityTokenService stsClient;
    
    public Credentials assumeRole(String roleArn, String sessionName) {
        AssumeRoleRequest request = new AssumeRoleRequest()
            .withRoleArn(roleArn)
            .withRoleSessionName(sessionName)
            .withDurationSeconds(3600); // 1 hour
            
        AssumeRoleResult result = stsClient.assumeRole(request);
        return result.getCredentials();
    }
}
```

**2. Spring Boot Service with Temporary Credentials:**

```java
@Service
public class TemporaryCredentialsSQSService {
    
    @Autowired
    private AssumeRoleService assumeRoleService;
    
    private final String SQS_ROLE_ARN = "arn:aws:iam::123456789012:role/SQSAccessRole";
    
    public void sendMessageWithTemporaryCredentials(String queueUrl, String message) {
        // Assume role and get temporary credentials
        Credentials credentials = assumeRoleService.assumeRole(
            SQS_ROLE_ARN, 
            "SQSSession-" + System.currentTimeMillis()
        );
        
        // Create SQS client with temporary credentials
        BasicSessionCredentials sessionCredentials = new BasicSessionCredentials(
            credentials.getAccessKeyId(),
            credentials.getSecretAccessKey(),
            credentials.getSessionToken()
        );
        
        AmazonSQS sqsClient = AmazonSQSClientBuilder.standard()
            .withCredentials(new AWSStaticCredentialsProvider(sessionCredentials))
            .withRegion(Regions.US_EAST_1)
            .build();
            
        // Send message
        sqsClient.sendMessage(queueUrl, message);
    }
}
```

**3. Automatic Credential Refresh:**

```java
@Component
public class RefreshableCredentialsProvider implements AWSCredentialsProvider {
    
    private final String roleArn;
    private final AWSSecurityTokenService stsClient;
    private volatile AWSCredentials credentials;
    private volatile Date credentialsExpiration;
    
    public RefreshableCredentialsProvider(String roleArn) {
        this.roleArn = roleArn;
        this.stsClient = AWSSecurityTokenServiceClientBuilder.defaultClient();
        refreshCredentials();
    }
    
    @Override
    public AWSCredentials getCredentials() {
        if (needsRefresh()) {
            synchronized (this) {
                if (needsRefresh()) {
                    refreshCredentials();
                }
            }
        }
        return credentials;
    }
    
    private boolean needsRefresh() {
        return credentials == null || 
               credentialsExpiration == null ||
               credentialsExpiration.before(new Date(System.currentTimeMillis() + 60000)); // Refresh 1 min early
    }
    
    private void refreshCredentials() {
        AssumeRoleRequest request = new AssumeRoleRequest()
            .withRoleArn(roleArn)
            .withRoleSessionName("AutoRefreshSession-" + System.currentTimeMillis())
            .withDurationSeconds(3600);
            
        AssumeRoleResult result = stsClient.assumeRole(request);
        Credentials creds = result.getCredentials();
        
        this.credentials = new BasicSessionCredentials(
            creds.getAccessKeyId(),
            creds.getSecretAccessKey(),
            creds.getSessionToken()
        );
        this.credentialsExpiration = creds.getExpiration();
    }
    
    @Override
    public void refresh() {
        refreshCredentials();
    }
}
```

**4. Integration with Spring Boot Application:**

```java
@Configuration
public class SecuritySQSConfig {
    
    @Value("${aws.iam.role.arn}")
    private String roleArn;
    
    @Bean
    public AWSCredentialsProvider refreshableCredentialsProvider() {
        return new RefreshableCredentialsProvider(roleArn);
    }
    
    @Bean
    public AmazonSQSAsync secureAmazonSQSAsync() {
        return AmazonSQSAsyncClientBuilder.standard()
            .withCredentials(refreshableCredentialsProvider())
            .withRegion(Regions.US_EAST_1)
            .build();
    }
}

@Service
public class SecureSQSMessageService {
    
    @Autowired
    private AmazonSQSAsync amazonSQSAsync;
    
    @SqsListener("${queue.secure.name}")
    public void processSecureMessage(@Payload String message, 
                                   @Header Map<String, Object> headers) {
        // Process message with secure credentials
        log.info("Processing secure message: {}", message);
    }
    
    public void sendSecureMessage(String queueName, Object message) {
        QueueMessagingTemplate template = new QueueMessagingTemplate(amazonSQSAsync);
        template.convertAndSend(queueName, message);
    }
}
```

### Best Practices for Temporary Credentials:

1. **Short Duration**: Use minimum required session duration
2. **Least Privilege**: Grant only necessary permissions
3. **Automatic Refresh**: Implement credential refresh before expiration
4. **Secure Storage**: Never log or persist temporary credentials
5. **Monitoring**: Track role assumptions and credential usage
6. **Error Handling**: Implement retry logic for credential refresh failures
