# 01 — AWS SES Introduction & Core Concepts

---

## What is Amazon SES?

Amazon Simple Email Service (SES) is a **fully managed cloud-based email sending service** designed for digital marketers and application developers to send marketing, notification, and transactional emails at scale.

- **Fully managed** — no email server setup or management required
- **High deliverability** — built-in reputation management and authentication support
- **Global availability** — regional email sending endpoints
- **Cost-effective** — pay-as-you-go, no upfront costs
- **Integration ready** — works natively with AWS services (SNS, CloudWatch, Kinesis, Lambda)

---

## Core Concepts Glossary

| Term | Definition |
|---|---|
| **SES Identity** | A verified email address or domain authorized to send email |
| **Sandbox Mode** | Restricted sending environment for new accounts |
| **Send Rate** | Maximum emails per second |
| **Send Quota** | Maximum emails per 24-hour period |
| **Hard Bounce** | Permanent delivery failure (invalid email address) |
| **Soft Bounce** | Temporary delivery failure (full mailbox, server unavailable) |
| **Complaint** | Recipient marked the email as spam |
| **Suppression List** | Auto-maintained list of addresses SES will not deliver to |
| **Configuration Set** | Named group of rules for tracking and routing email events |
| **DKIM** | Cryptographic signature proving email authenticity |
| **SPF** | DNS record authorizing IP addresses to send for a domain |
| **DMARC** | Policy layer combining SPF and DKIM results |

## SES Identity Types

### Verified Email Address

- A specific email address individually verified for sending
- AWS sends a confirmation link to the address to verify ownership
- Each address must be verified separately
- Best for: testing, small-scale sending, specific sender addresses

### Verified Domain

- An entire domain (e.g., `mycompany.com`) verified via DNS record
- Can send from **any address** within that domain (`orders@`, `noreply@`, etc.)
- Automatically covers all subdomains
- Supports DKIM for all addresses in the domain
- Best for: production applications, consistent brand identity

### Identity Verification Status

| Status | Description |
|---|---|
| `Pending` | Verification in progress |
| `Success` | Successfully verified — can send |
| `Failed` | Verification failed — must retry |
| `TemporaryFailure` | Temporary issue — SES will retry |
| `NotStarted` | Verification not yet initiated |

## Sandbox Mode

Every new SES account starts in **sandbox mode** — a restricted environment to prevent abuse and protect service reputation.

### Sandbox Restrictions

| Limit | Sandbox Value |
|---|---|
| Daily send quota | 200 emails per 24 hours |
| Send rate | 1 email per second |
| Recipients | Only verified email addresses |
| Max recipients per message | 50 |

### Moving to Production

Submit a **production access request** in the AWS console (Support Center → Service limit increase → SES). You'll need to describe your use case, expected volume, and how you handle bounces and complaints.

---

## Sending Limits

SES enforces limits to protect service quality and IP reputation.

| Limit | Description | Threshold |
|---|---|---|
| **Send Rate** | Max emails per second | Starts at 1/s; increases with reputation |
| **Send Quota** | Max emails per 24 hours | Starts at 200; increases with reputation |
| **Bounce Rate** | Hard + soft bounces / total sent | Must stay **below 5%** |
| **Complaint Rate** | Spam complaints / total sent | Must stay **below 0.1%** |

> Limits increase **automatically** based on consistent, responsible sending behavior. You can also request increases via the AWS console.

## Email Lifecycle States

```
Producer (your app)
    │
    │ SendEmail()
    ▼
[SEND] — SES accepts the email
    │
    ├── [REJECT] — SES rejects due to policy or content issues
    │
    ├── [BOUNCE] — Recipient mail server could not deliver
    │       ├── Hard Bounce → add to suppression list
    │       └── Soft Bounce → retry possible
    │
    ├── [COMPLAINT] — Recipient marks as spam
    │       └── Add to suppression list
    │
    └── [DELIVERY] — Successfully delivered to recipient
            │
            ├── [OPEN] — Recipient opens email (if tracking enabled)
            └── [CLICK] — Recipient clicks a link (if tracking enabled)
```

## SES Email Anatomy

Each SES email includes the following components:

| Component | Description | Required |
|---|---|---|
| **Message ID** | Unique identifier assigned by SES | Auto-assigned |
| **From Address** | Sender address — must be a verified identity | Yes |
| **To / CC / BCC** | Recipient email addresses | Yes (To) |
| **Subject** | Email subject line | Yes |
| **Message Body** | HTML and/or plain text content | Yes (at least one) |
| **Headers** | Additional email metadata | Optional |
| **Attachments** | File attachments (via Raw email) | Optional |
| **Configuration Set** | Event tracking and routing rules | Optional |
| **Tags** | Key-value pairs for categorization | Optional |

## Bounce and Complaint Handling

### Bounce Types

| Type | Cause | Action |
|---|---|---|
| **Hard Bounce** | Invalid or non-existent email address | Remove permanently from lists |
| **Soft Bounce** | Mailbox full, server temporarily unavailable | Retry with backoff; remove if persistent |
| **Complaint** | Recipient marked as spam | Remove immediately; add to suppression list |

### Suppression List

SES automatically maintains a suppression list of addresses that have hard-bounced or complained. SES will **refuse to deliver** to suppressed addresses to protect your reputation.

- Addresses are added automatically on hard bounces and complaints
- You can also add addresses manually via the console or API
- You can remove addresses from the list if you have confirmation they are valid

---

## Configuration Sets

A configuration set is a **named group of rules** applied to a specific email-sending stream. They let you:

- Publish email events (send, bounce, complaint, delivery, open, click) to CloudWatch, SNS, Kinesis, or EventBridge
- Track reputation metrics separately for different email streams
- Configure IP pools and delivery options per sending scenario
- Apply message tags for categorization and cost allocation

**Example use case**: separate configuration sets for `transactional-emails` and `marketing-emails` — this isolates their reputations so a marketing bounce spike doesn't affect transactional delivery.

## SES vs Other Email Services

| Feature | Amazon SES | SendGrid | Mailgun |
|---|---|---|---|
| **Management** | AWS-native, fully managed | SaaS | SaaS |
| **Pricing** | $0.10 / 1,000 emails (cheapest at scale) | Starts free, higher at scale | Starts free, usage-based |
| **AWS Integration** | Native (IAM, CloudWatch, SNS, Lambda) | Requires API | Requires API |
| **Setup Complexity** | Moderate (DNS records, verification) | Low | Low |
| **Template Support** | Yes | Yes | Yes |
| **Analytics** | Via CloudWatch / event publishing | Built-in dashboard | Built-in dashboard |
| **Best For** | High-volume, AWS-native apps | Developer-friendly SaaS | Transactional email focus |
